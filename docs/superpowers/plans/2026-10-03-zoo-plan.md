# Zoo web port implementation plan

**Goal:** Ship one playable, touch-friendly zoo level to public GitHub Pages.
**Architecture:** Dependency-free static DOM game with a pure state machine; original raster artwork retained. Independent project preserves downloaded upstream source.
**Tech stack:** HTML, CSS, JavaScript ES modules, Node test runner, GitHub Pages.

1. Create tests/state.test.js before src/state.js; run `node --test` and observe missing implementation failure. Cover start, nearby encounters, wrong retries, three successes, goal gating, restart and movement bounds.
2. Implement src/state.js with createGame/start/move/encounter/answer/continueGame/restart; movement clamped to walkway and blocked while in dialogue/feedback.
3. Create index.html, styles.css and src/main.js. Render original ZOO scene, sprites, accessible controls and native dialogs. Bind click-to-walk, pointer buttons and keyboard; add opt-in browser voice with silent fallback. Follow concept palette and spacing, preserving all three encounter states and completion flow.
4. Run unit tests and local server. Verify start → movement → incorrect answer → retry → all correct → return to gathering point → win → restart. Check portrait, keyboard/dialog focus, static URLs and audio cancellation.
5. Preserve LICENSE, attribution and original data. Publish independent repository baby-36-web, main root Pages. Check built deployment and public assets, save user instructions.
